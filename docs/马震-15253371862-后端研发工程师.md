## 项目经历

### AI 智能创作平台（ArtArch.AI，2025 年 12 月 ~ 至今）

**项目背景：** 面向 AI 短视频 / 图片 / 音频创作场景，搭建一个生产级 Agent 创作平台。用户通过自然语言提出创意需求，系统自动完成创意核打磨、脚本规划、分镜设计、音乐 / 转场建议、DAG 工作流生成、素材生成与发布准备，降低从想法到可执行多模态工作流的门槛。

**技术栈：** Python / FastAPI、**LangGraph**、Gemini、SSE、Redis、PostgreSQL、S3 / CDN、Kubernetes。

- **Agent Runtime 架构：** 基于 **LangGraph** 设计多阶段状态机，将复杂创作任务拆为意图识别、规格确认、故事方案、核心元素、分镜、音乐音效、DAG Draft 等可控节点；使用 `thread_id=session_id` 管理会话，支持 Checkpoint、Interrupt/Resume、断线重连与历史回放，**单 session 支持 50+ 轮上下文，断线恢复成功率 99%+**。
- **Planner + 确定性装配：** 使用 Gemini Planner 负责创意理解、分镜规划和工作流选择，要求模型按 JSON Schema 输出；最终 DAG 由确定性 DraftGenerator 装配。**相比 LLM 直接生成 DAG，一次性可执行率从 ~55% 提升至 95%+**，幻觉节点和非法 edge 基本归零。
- **真实模板蒸馏：** 从线上真实 DAG / Canvas 数据中抽取 workflow refs、edge targetHandle、flow_info 节点布局、输入槽位和输出 schema，形成可复用 Draft Pattern，让模型生成结果更贴近产品真实工作流。
- **双层意图解析：** 高频指令（继续、重试、选择 A/B/C、修改某个镜头）先用规则/正则零成本解析，歧义场景再交给 LLM Classifier，**规则层覆盖约 70% 高频指令，LLM 调用成本下降约 40%**，平均意图解析延迟 < 50ms。
- **Responses-style 流式协议：** 设计 `/v1/responses` SSE 输出，统一发送 `stage.started`、`planner.delta`、`dag.updated`、`validation.report`、`message.completed` 等事件，**首 token 延迟稳定在 1.5s 以内**，前端可实时展示 Agent 思考、阶段推进和 DAG 变化。
- **DAG 工具链：** 打通 DAG 生成、Registry Guard 校验、custom_config/slot 抽取、DAG Patch、远程执行、状态轮询、Trace 查询、Cancel、Publish Command 生成，实现从对话到可执行工作流的闭环。
- **多模态节点编排：** 支持文本、图片、视频、音频节点组合，**沉淀 30+ 种节点类型，覆盖 T2I、I2I、T2V、首尾帧视频、音乐生成、视频拼接 6 大类链路**；DAG 作为唯一真相源，前端 Canvas 只负责渲染和交互。
- **工程可靠性：** 建设 session / run / message / event / checkpoint 投影模型，补齐日志、错误码、重试退避、模型 Fallback、上下文预算、CORS、SSE 反代缓冲等生产化细节，使 Agent 服务具备可排查、可恢复、可演进能力。

**核心成果：** DAG 一次性可执行率 ~55% → 95%+；首 token 延迟 < 1.5s；规则意图层覆盖约 70%，LLM 调用成本下降约 40%；多模态节点扩展至 30+ 种，覆盖端到端创作链路。

- **独立负责** 对话 Bot **多轮状态机**设计，将用户问题按症状咨询、疾病科普、药品问答、报告解读、挂号 / 科室推荐等意图路由到不同处理策略，并沉淀症状上下文、已确认信息与待追问字段，使 Bot 从一次性问答升级为连续问诊式交互，**多轮意图识别准确率 92%+，平均对话深度 3.5 轮**。
- **主导 RAG 问答链路重构**：围绕医学百科、疾病库、药品库、科室 / 医生等知识源建设召回 → 过滤 → 重排 → 引用组织 → 答案生成全链路；引入 **BM25 + Dense 混合检索 + bge-reranker 重排**，**Top-3 命中率从 ~70% 提升到 88%+**，并通过引用溯源和片段对齐显著降低医学幻觉风险。

- **Prompt 与评测闭环：** 建设 Prompt 模板版本管理、医学领域评测集（千级标注样本）和 Badcase 回流机制，通过线上问题回放、人工标注与规则修正持续迭代回答准确性与稳定性。

**核心成果：** RAG Top-3 命中率 ~70% → 88%+；意图识别准确率 92%+；高风险拦截召回率 98%+；日均十万级 query 稳定服务。

**技术栈：** Golang / Gin、MySQL、Redis、Kafka、规则引擎、传统判别模型、LLM。

- **负责** POI UGC 上报服务与工单离线流转流程建设，覆盖端上上报、数据标准化、任务分发、审核状态流转、结果回写和异常兜底。
- **设计机审服务分层管线：** 将规则校验、特征抽取、历史可信度、文本语义判断、地理位置一致性和人工复核策略组合为"规则先行 + 传统模型 + LLM 辅助 + HITL"四层架构，每层只把不确定样本上抛，最大化利用低成本档位。

- **可解释审核：** 模型输出附带理由与命中规则，支持质检回查与策略回溯，保留人工复核兜底通道。
